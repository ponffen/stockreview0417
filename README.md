一、数据与账户口径
子股票账户

日终快照里：总资产、净出入金、序列类指标一律用 账户默认账本币 存储；列名、接口字段与 币种元数据（如 book_ccy）一致，避免误读成人民币。
出入金归属日：严格使用 cash_transfers（出入金记录）里填写的日期。
总账户（全部）

单独一行（如 account_id = 'all'）：总资产、净出入金、以及由此派生的序列与区间结果一律为人民币。
合并规则：在每个交易日，用 各子账户当日快照中已与「当日总资产」同一套口径的汇率，将子账户本币折算为人民币后加总；不在合并时另拉一套与当日快照不一致的汇率源。
规则版本 rule_version

每次 收益 / 收益率定义、序列构造、合并规则 发生不兼容变更时：全局或按任务递增 rule_version。
读写缓存时：只消费当前生效的 rule_version；旧版本行可异步清理。
主键仍为五元组；rule_version 为列，用于筛选与防脏读（不必塞进主键亦可，与此前结论一致）。
二、日终快照表（真相源，按日一行）
用途：任意自然日 日终已冻结 后，该日及以前的数据以本表为权威；不依赖原始成交重算历史。

每行至少承载（语义说明，不写公式）

交易日：自然日或交易日键，与现有习惯一致。
total_assets（总资产）：子账户为 账本币；all 为 人民币。含义为日末台账与持仓估值后的 账户总财富。
当日净出入金：仅由 cash_transfers（出入金记录） 按归属日汇总，入正出负；不含股票成交作为现金流；迁移、初始录入等 一律计入，不做业务剔除。
时间加权相关：按 「总资产版」 日链计算并写入的 日度结果与可链式累计量（字段名与现网可延续或重命名，但语义须与「总市值旧版」彻底切割；历史需 按新定义回填覆盖）。
其他已有辅助列（如现金、市值、汇率等）：继续服务展示、校验、合并；收益类主读字段以总资产与纯出入金为准。
三、六个固定预设的区间缓存（performance_series_cache 或等价表）
用途：分析页在六个预设（最近一周、最近一月、最近三月、月初至今、年初至今、历史以来）下，曲线与末值尽量整段读库，不在前端重算。

主键维度（五元组）

user_id：用户。
account_id：子账户或 all。
as_of_date：冻结基准日（通常为 日终完成后的业务日，即「数据已算到哪一天」；与下节「今日」策略衔接）。
preset：上述六选一。
algo：至少区分 时间加权 与 资金加权（XIRR） 所需产物；若时间加权与资金加权存不同结构，可分多条或分字段。
列 rule_version

与第二节一致；公式或合并规则变更后重算并写入新 rule_version。
每个预设每条缓存存「整段日序列」成品（建议放在 series_json 或结构化列中）

公共轴：dates（区间内每个展示日，顺序严格递增）。
总资产序列：与展示币种一致（子账本币 / all 人民币）。
净出入金序列：与展示币种一致，与快照日行的汇总 同源。
时间加权收益率展示序列：已在服务端完成 「相对区间首日前一日为零点」 的链式展示处理，前端 逐点描线 即可。
累计收益金额展示序列：同样完成 相对区间首日前一日为零点 与 「总资产 + 纯出入金」 口径下的逐日金额，前端 逐点描线。
资金加权（XIRR）：不生成日度收益率曲线；在该 algo 下可仅存 区间末标量（如年化或统一约定的展示收益率）及 可选说明字段（与 UI 文案一致：仅总值、无日走势）。
读取约定

分析页选中某预设、某账户：按五元组 + 当前 rule_version 读一条；将 dates 与各类序列 原样下发。
历史段：禁止为画线再去拉全量 trades 重算。
四、「今日」策略：昨日末以前全读库 + 今日一段实时
目标：既不违背「历史尽量读库」，又避免「为盘中每分钟写满缓存」。

昨日末（含）以前

总资产日序列、净出入金、TWR 链、六个预设的 series_json：一律来自 第二节快照 + 第三节缓存，读库即可。
今日（未日终冻结的当前业务日）

单独提供「实时/准实时接口」（或与主接口分块返回）：在 昨日日末总资产 与 昨日及以前已冻结的出入金 基础上，叠加 当前行情与台账得到的此刻总资产，以及 今日已记账的净出入金。
时间加权：在服务端用 「昨末 → 今刻」 接一小段 日链或等价的展示增量，与历史缓存 拼接后返回；前端仍 不计算链，只画 服务端给好的今日最后一个点或今日小序列（由你们定 UI 是阶跃还是日内多点）。
资金加权 XIRR：可对 「本预设区间 + 今刻终点」 在服务端 现算一个数 返回；不画日度资金加权曲线（与已定产品一致）。
日终完成后

跑完冻结与缓存重建后：「今日」并入快照与缓存；下一日打开时，前一日也变为 纯读库。
五、各指标「计算方式」（纯语言，无公式）
1. 累计收益金额（展示曲线与区间末值）
含义：在选定区间内，总资产 相对 「区间首日前一日日末」 的变化，再 剔除区间内仅由出入金带来的增减；相对 首日前一日 归零后得到 逐日曲线；区间 最后一天（或今刻） 的值为 区间末累计收益。
历史：日终已把 每日总资产与每日净出入金 写入快照；区间缓存里已把 整段展示序列 写好，直接读库。
今日：实时接口在 昨末基准 上补 今刻总资产与今日净出入金，服务端拼出 今日末点或今日小序列，前端只渲染。
2. 时间加权收益率（TWR）
含义：在 剔除当日净出入金对分母的扭曲方式 与你们选定的 日链定义 下，用 相邻两日总资产 与 当日净出入金 得到 每日收益率因子，从 区间首日前一日 起 链式累计；展示时再 相对首日前一日归零。股票买卖 不单独作为现金流项，只体现在 两日总资产变化 中。
历史：日终写入 总资产版 日链相关量；六个预设的 展示序列 在缓存中 已 rebase 好，直接读库。
今日：服务端把 最后一段链接到今刻，前端 不链式重算。
3. 资金加权收益率（XIRR）
含义：把 区间首日前一刻的总资产、区间内各出入金日期与金额、区间结束时刻（或日末）的总资产 编成 带日期的现金流，求 内部收益率（再按产品约定转成 年化或区间展示形态）。不含股票成交现金流。
历史：对六个预设，在 as_of 冻结时算好，与 末值 一并存入缓存；不存日度资金加权率曲线。
今日：可对 「同一现金流结构、终点换为今刻总资产」 在服务端 临时算一个数 返回；仍不提供日走势。
4. 自定义区间
不进入六个预设的预计算行（或仅存短 TTL 的临时缓存，可选）。
服务端：按用户选的 起止日期，从快照 只读 拉出 从「起始日前一日」到「结束日」」 的 日末总资产与净出入金，在服务端 跑一次 与上相同的 累计收益、TWR 序列、XIRR 标量；不把原始 trades 下发给前端。
若开启短 TTL 缓存：键除五元组外增加 自定义起止日，减少重复拖拽计算。
六、「历史数据前端零算、服务端也尽量读库」总流程
日终任务：写/更新 日快照（总资产、纯出入金、总资产版 TWR 相关）；按用户与账户 重建六个预设 的 series_json 与 XIRR 末值；写入 rule_version 当前值；all 行用 当日各子快照一致汇率 合并。
分析页打开（非自定义）：服务端 按五元组 + rule_version 读缓存；附带 今日小补丁接口 的合并结果 一次性返回；前端 只画图与展示数。
分析页打开（自定义）：服务端 读快照区间 → 一次计算 → 可选写短 TTL；前端同样 零重算。
发版改规则：提升 rule_version，清空或废弃旧版本缓存，按新规则全量重算回填；直至完成前可对读 降级提示（可选）。
